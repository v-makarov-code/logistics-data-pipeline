# Локальная база данных

Запуск из корня проекта:

```powershell
docker compose up -d
docker compose ps
docker compose logs -f postgres
```

Первый запуск может занять несколько минут: PostgreSQL выполняет `sql/schema.sql`, затем `sql/synthetic.sql`, `sql/03_core_and_quarantine.sql`, `sql/04_mart_route_card.sql` и `sql/06_mart_ml_price_predictions.sql`. Они создают источник, пустые таблицы Core, карантина и витрин, а также справочник групп кузова. По умолчанию генератор создаёт 300 000 сделок. После состояния `healthy` сервис `etl` заполняет Core и карточку маршрута, затем сервис `ml` готовит признаки, обучает CatBoost и публикует прогнозы в PostgreSQL. Артефакты ML сохраняются в `ml/artifacts`; завершение этапов видно через `docker compose logs etl ml`.

При пустом томе эти SQL-файлы выполняются один раз. При последующих запусках существующая база сохраняется. Если инициализация завершилась ошибкой, повторный запуск контейнера сам по себе не продолжит её: сначала изучите журнал и определите безопасный способ восстановления.

Добавленный DDL не выполняется автоматически на уже заполненном томе. Для существующей установки примените `sql/06_mart_ml_price_predictions.sql` к текущей БД один раз; том удалять не требуется. Команда и инструкция повторной публикации готовых прогнозов находятся в `ml/README.md`.

pgAdmin доступен по адресу http://localhost:5050. Логин и пароль по умолчанию: `admin@example.com` / `local_admin_password`. При регистрации сервера в pgAdmin используйте:

| Поле | Значение по умолчанию |
| --- | --- |
| Host name/address | `postgres` |
| Port | `5432` |
| Maintenance database | `deals_bigdata` |
| Username | `de_user` |
| Password | `local_de_password` |

Для подключения с компьютера используйте `localhost:5432`; имя `postgres` доступно внутри сети Compose. Пароли предназначены только для локальной разработки. Необязательно копировать `.env.example`: Compose использует эти же значения по умолчанию. Чтобы их переопределить, скопируйте файл в `.env` и измените значения до первой инициализации. Изменение переменных пользователя и базы не обновляет уже созданную базу или существующий аккаунт pgAdmin.

Проверка из PowerShell:

```powershell
docker compose exec postgres psql -U de_user -d deals_bigdata -c "SELECT count(*) FROM prices;"
```

Команда выше использует значения по умолчанию; если они изменены, укажите свои. Остановить контейнеры без удаления данных: `docker compose down`. Команда `docker compose down -v` удаляет тома и все данные базы и pgAdmin.
